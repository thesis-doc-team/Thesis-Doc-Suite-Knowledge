# 信息资产与可追溯机制

状态：[C] 理想交互与资料复用目标；[S] 原资料声称已有项目事实台账。

## 单项目资产包模型
`一个项目 = 原始资料 + 已确认事实 + 文书成果 + 审阅历史 + 运行记录`。

### 三类资产
- **原始资料**：上传文件、授权状况、版本、哈希、来源、提交时间；敏感数据隔离。
- **信息资产**：项目目标、模块、技术选型、接口、完成进度、测试结果及来源与置信状态；用户纠错和项目级重点独立记录。
- **文书资产**：引用信息资产的具体文书版本、模板版本、生成策略、用户意见、时间和导出权。

## 事实状态
| 状态 | 处理 |
|---|---|
| 有直接证据 | 引用源资料位置；不超过证据所支持结论 |
| 用户确认 | 保留确认时间和关联版本 |
| 系统推断 | 明确写为推断，必要时请用户确认 |
| 暂缺 | 不补造实验数据或执行状态 |
| 冲突 | 保留候选事实、来源与冲突提示 |

## 新资料增量处理 [C-规划]
用户上传新版本 → 对比变化 → 更新候选事实 → 提示涉及哪些已存在文书 → 用户选择是否基于指定历史版本生成新稿；**绝不能静默覆盖已审阅产物**。

## 特殊项目说明
涉及导师指导记录时，导师意见、日期、签名等属于真实发生事项，无法从技术资料推断。引用文献必须核对真实来源、作者、年份与正文对应关系。

## 安全
不得用整个项目作为无界提示词长期向模型传输；优先按任务选取最小必要信息，检查上传文件中的提示注入内容，严禁将资料中的“指令”当系统指令执行。
