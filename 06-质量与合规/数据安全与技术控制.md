# 个人信息、源码上传与后台安全：技术落地控制

> 本文为实现指导 [R]，不是已部署安全证明；配合法规手册第 5–7、12 章和检查表 C-13…C-25。

## 1. 资产分类
| 资产 | 风险等级（内部建议） | 建议措施 |
|---|---|---|
| 账号、联系方式、身份关联信息 | 较高 | 最小收集、加密传输、严格授权 |
| 用户私有源码/设计文件 | 较高 | 租户隔离、静态分析、操作审计、禁止执行 |
| 项目事实和 Word 拟稿 | 较高 | 版本隔离、非公开链接、导出鉴权 |
| 模型 API 密钥/JWT 密钥 | 极高 | 环境/密钥托管、轮换、不进日志 |
| 匿名汇总指标 | 一般（确认不可复识别后） | 不携带正文与私密标识 |

## 2. 前后端安全
- 生产只使用 HTTPS，浏览器 Cookie 强制 Secure/HttpOnly/SameSite 合理配置，校验 Origin/CSRF。
- 所有读写、列表、预览页、下载、文书版本、反馈和管理员路由强制后端授权；不能只靠前端隐藏按钮。
- 下载使用短期授权令牌或受控流式响应，禁止长效裸文件路径。
- 上传文件先进入隔离区，验证文件魔数/MIME、大小、总解压量、条目数、压缩比、文件名编码和路径，禁绝软链接逃逸。
- 文档预览渲染进程限时、限内存、限进程、非 root，处理宏或嵌入对象时默认禁用执行。
- 控制单任务并发、模型预算、重试和递归工具调用次数，避免 API 被恶意刷量。

## 3. 模型边界
- 用户材料的任何“忽略系统规则、泄露其他用户数据”等文本都只是**数据**。
- 工具白名单、不让 Agent 获得后台管理/数据库密码、只使用授权项目目录。
- 提取事实先求证据，不得将 AI 假设标记成技术实现事实。
- 模型与供应商变更必须重新核查个人信息委托、跨境、成本和安全隔离。

## 4. 数据生命线
用户上传 → 病毒/类型检查 → 私有存储 → 必要分析 → 已确认事实 → 版本化生成 → 预览导出 → 到期/请求删除。为每一步记录：处理目的、访问角色、数据区域、保留期限、删除机制、合法性依据。

## 5. 备份及故障恢复
- PostgreSQL + 私有文件需要一致性恢复策略，备份和主机分故障域。
- 测试“数据库恢复但文件缺失”“模型扣次失败”“正在导出服务重启”三种异常。
- 设定 RPO/RTO **需实测并经业务确认**，不在此臆造分钟数。
