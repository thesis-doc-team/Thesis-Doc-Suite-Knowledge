# Thesis Doc Suite｜中国大陆网站合规执行手册（详细版）

> **状态：[R] 内部风险识别和行动方案；涉及审批、业务定性、实际备案和供应商条款均标 [V]。**
>
> 适用假设：2026-11-09；首期拟部署**中国大陆云服务器**；面向**中国大陆高校学生**；目前**无营业执照**，一人主导持有经营、其他成员合作；现阶段先本地内部测试，之后在一所高校熟人邀请试点，最终再评估正式收费。
>
> 这份手册**不是法律意见书、许可证明或办理回执**。涉及增值电信许可、AI 服务登记、域名备案主体、教育相关审批、数据出境等，应在明确主体、服务器省份、业务说明和模型服务链路后向属地机构或专业人士确认。

## 0. 执行摘要：什么会阻止上线？

### 绝对不能用“微创业”规避的项目
1. 未满足**适用的备案/许可**条件，不得将中国大陆公网网站按经营计划直接开放。
2. 未落实用户个人信息告知、最小必要数据处理、数据安全及授权访问，不得邀请学生上传真实资料。
3. 不清楚生成式 AI 服务及模型 API 调用适用登记/备案义务，不应自行假设第三方模型已经备案就覆盖自己的网站。
4. DOCX、HTML、预览和导出涉及的 AI 生成内容标识方式没有完成适用性与技术核验，不得轻率认定首页“AI辅助”提示已经足够。
5. 出现跨用户读取、未经授权的导出、重大事实伪造、无法恢复数据或严重官方模板损坏时，应暂停对应功能对外开放。
6. 收款前未确认市场主体资格、支付接入资格、具体业务许可边界、价格/服务与退款条款，不进行收费试点。

### 三个阶段不是一套手续
| 阶段 | 行为 | 合规焦点 | 放行逻辑 |
|---|---|---|---|
| S0 内部研发 | 本机/非公开环境、授权测试数据、不对公众提供生成 | 设备/人员权限、源码授权、供应商条款、必要安全控制 | 可开展研发；不以此替代未来公网手续 |
| S1 邀请制免费试点 | 国内公网网站向外部学生提供有限 AI 文书辅助 | ICP及适用手续、AI 应用定性、账号/隐私/标识/安全、内容管理 | **邀请制/免费不自动免备案、AI或隐私义务** |
| S2 公开收费经营 | 服务包销售、支付、退款、客户售后、潜在扩大公域传播 | S1 全部 + 主体登记/经营定性/支付/合同/税务/消费者权益 | 全部收费前置关口满足后再交易 |

## 1. 经营主体与业务定性

### 1.1 已知业务描述 [C]
自营 AI 文档辅助网站：学生上传其有权处理的项目资料，系统通过第三方大模型 API 提取事实、生成参考文书、按官方或用户模板编排 DOCX、在线预览/审阅/修订、按权限导出。当前不打算为外部商家提供入驻销售、交易撮合或商品交易平台功能。

### 1.2 当前主体方案 [V]
- **无营业执照的自然人/团队**：适合先完成本地内部测试；并非当然能以个人非经营性网站备案承接未来收费。
- **个体工商户**：小规模一人经营的第一候选，但经营者通常承担个人经营债务的个人责任；还要核查实际业务的备案、许可与支付产品资格。
- **一人有限责任公司**：如果电信许可等要求公司申请人、风险隔离或合约经营需要，可研究此路线；公司需要依法实缴/认缴出资、税务和治理，不是完全零管理成本。见 [L05][L21]。

### 1.3 不要犯的四种误判
- ❌ “第一年交易额不超过 10 万，所以不需要任何手续”：网络交易登记例外不等于ICP备案、特定经营许可、纳税和个人信息规则豁免。[L14]
- ❌ “ICP备案了，任何收费 SaaS 都可以经营”：ICP备案与电信经营许可/支付商户/市场主体登记不相互替代。[L01][L05]
- ❌ “收费就必须办 ICP 经营许可证”：多地通信管理局明确，自营网站直接销售自身或第三方商品/服务、无第三方以其名义入驻销售的一类情形，可能不属于增值电信业务；实际 **AI 在线处理服务定性需属地确认**。[L03][L04]
- ❌ “注册个体工商户就什么许可都能申请”：若实际需要增值电信业务经营许可，申请主体通常要求依法设立公司；不能直接用个体工商户替代。[L05]

### 1.4 业务定性必须提交给主管部门的文字 [R]
> 拟经营一个自营 AI 文书辅助网站，用户上传有权使用的源码与技术资料，系统通过第三方已核验的模型 API 提取与组织信息，输出参考拟稿，并提供 DOCX 模板编排、全文预览、修改、版本和受限导出。平台没有第三方商家以独立名义入驻销售，不提供交易撮合，不公开用户私人文书。首期邀请制试用，未来计划以单项目服务包收费。请就此实际业务说明是否需要增值电信业务经营许可、适用业务类别、主体资格与备案规则。

**必须保存**：咨询日期、属地通信管理局、业务说明版本、答复原文/截图/编号、负责人、下一步行动。口头答复需注明“口头，待复核”。

## 2. ICP 备案、域名和公网部署

### 2.1 国家层面的依据
《互联网信息服务管理办法》区分经营性互联网信息服务的许可和非经营性互联网信息服务备案；适用行为需要按相应程序办理，不应先公网服务再“慢慢补”。网站主页需按规定展示适用的许可/备案编号，业务与主体变动需要按规则办理变更。[L01][L02]

### 2.2 低成本办理路径 [R]
1. 先明确经营主体与网站业务类别，再购置符合备案条件的域名/大陆接入资源。
2. 检查域名实名认证主体与申请主体的一致性以及接入商备案要求。
3. 通过中国大陆云接入商的备案系统提交主体信息、负责人、域名、网站名称、服务说明等所需材料。
4. 接入商初审、管局审核，取得有效备案后按条件开放域名访问；首页展示备案编号与必要链接。
5. 记录备案号、主体、域名、接入服务商、省份、业务描述、完成日期及后续变更责任。

### 2.3 “个人备案先试点，后付费”有风险
个人非经营性备案不等于未来收费服务的经营资格；主体变化需要按当地管局和接入商的规则变更或重新备案，未必可以无缝迁移。不要在备案中把实际对外服务目的写成与经营事实不符的内容。[L01][L02]

### 2.4 公安联网备案 [V]
根据相关规定，网络正式联通后的适用备案义务通常涉及 30 日期限。实际网站办理要求以属地公安网安部门和服务平台为准；记录具体截止时间及回执，按当地要求在前台展示标识和链接。[L06]

### 2.5 其他可能触发的前置审批 [V]
互联网信息服务涉及教育、新闻、出版等特定业务可能另有主管部门审批要求。[L01] **提供本科毕设文书辅助**并不当然等同于须取得“教育类许可证”，但如果转向在线课程、培训、教育资质认证或出版发行，应重新定性。禁止把“学生用户”简单推导出“无需任何教育专项审批”。

## 3. 生成式 AI：备案、登记与供应商

### 3.1 适用范围的关键事实
《生成式人工智能服务管理暂行办法》适用于利用生成式 AI 技术**向中国境内公众提供**生成文本等服务；未向公众提供的企业/科研机构内部研发有范围上的区别。[L07]

“仅熟人可进”“邀请制”“用户很少”不当然等于内部研发；真实校外学生在公网上操作，需要单独判定属于哪类对外服务。[V]

### 3.2 已备案模型≠自己的应用天然免手续
2026-09-14 国家网信办公示：直接调用已备案模型能力的生成式 AI 应用或功能，存在地方网信部门登记路径，且提供具有舆论属性或者社会动员能力的服务可通过属地网信部门履行适用的备案或登记；已上线应用/功能按要求公示所使用已备案或登记服务名称和号码。[L08]

需要核实：
- 调用的具体模型/供应商备案号与实际 API 名称是否匹配；
- 第三方模型提供商是否为国内实际承载，是否存在转发至境外模型或第三方路由；
- Thesis Doc Suite 的自身服务/功能属于备案、登记还是其他适用路径；
- 是否有舆论属性/社会动员能力、是否公开传播用户文书；
- 何时申报、所需材料、展示格式和后续版本变化的更新规则。

### 3.3 供应商核验模板
| 字段 | 要求 |
|---|---|
| 服务商合同主体 | 公司名称、官网、合同/条款版本 |
| 模型标识 | 商业 API 名称、实际底层模型、备案/登记信息 |
| 数据处理 | 请求存储多久、是否用于训练、是否可关闭训练使用 |
| 数据落点 | 处理和备份服务器所在地、跨境转发情况 |
| 信息保护 | 分包处理、加密、安全事件通知、删除机制 |
| 审计证据 | 官方文件/合同截图、日期、模型变更记录 |

**原项目介绍记录**：[S] 采用百炼 `deepseek-v4.1-flash`，MiMo `mimo-v2.6-pro` 回退；本包未核实供应商的最新备案状态、API 实际路由和合同条款，不得按[S]推导合规完成。

## 4. AI 生成合成内容标识（DOCX 必查）

### 4.1 现行依据
《人工智能生成合成内容标识办法》自 2025-09-01 实施，规定适用情形的显式标识、文件元数据中的隐式标识，以及在提供下载/复制/导出时的要求；用户服务协议也应说明标识方法和样式。[L09][L10]

### 4.2 为什么本项目高风险
首期最关键的产品能力是**严格保留官方 DOCX 模板**。文书导出后不仅能在网站预览，还要供学生用 Word/WPS 打开。如果简单追加文字说明，可能破坏学校固定栏目、表格和页数；如果完全不加标识，又可能不符合适用法规。

### 4.3 技术研究和验收 [V]
- 判断**每类生成/编辑/模板填充产物**是否属于适用内容/显式标识要求，区别原样复制上传文件与 AI 新生成文本。
- 查看文书**页面**（预览提示）与**实际 DOCX 内容**（文本/适当可见标识）是否满足适用的显式标识要求；不能以网页说明替代必需的导出文件标识。
- 针对 DOCX 元数据设计可核验的隐式标识字段；不能只在数据库里保存 `ai_generated=true`。
- 依据配套标准/最新实践指南验证标识格式、编码、服务提供者标识、内容编号等。
- 维护导出日志、版本哈希、标识成功/失败记录；用户下载前进行标识完整性校验。
- **官方模板冲突**：不得擅自破坏原模板；确有法律允许的不带显式标识方式时，必须满足法律规定的适用条件和责任告知，不是默认绕过。

### 4.4 第九条的特别路径需要谨慎
《标识办法》第九条对**用户主动申请无显式标识**的特定情形规定了协议责任与至少六个月相关日志等要求；这不是“用户要我去掉我就可以去掉”的一般豁免，不能用于隐瞒 AI 生成来源、规避学校或其他机构明确的 AI 使用规则。[L09][L10]

### 4.5 放行标准
已确定适用分类 + 已实现并经过抽查的 DOCX/HTML 标识 + 协议说明 + 真实导出端到端测试 + 例外路径（如有）经确认。未完成前 `AI-04` 保持“待核查”，不得显示“已符合所有 AI 标识要求”。

## 5. 个人信息保护与真实学生资料

### 5.1 收集信息的来源和目的
平台可能处理注册邮箱/电话、学号（若用户自行填入）、导师姓名、毕业设计资料、源码注释中的个人信息、图片、图纸和项目成果。即使服务只面对本科学生，也不能假设所有资料都非敏感。[L11]

### 5.2 上线前要完成的数据清单 [R]
逐项列明：字段/文件种类、是否必要、收集环节、处理目的、法律处理依据、保留期限、存放地、访问角色、第三方接收方、删除路径、向用户展示的告知文本版本。

### 5.3 隐私告知最小章节
- 运营主体及联系方式（取得后填写真实信息）；
- 信息种类、处理目的、处理方式、必要性；
- 上传项目源码、文书、图表和个人信息在系统中的用途；
- 模型 API/云存储/短信或邮件供应商的身份与相关处理方式；
- 资料存储地点、原则性的保留规则与例外；
- 用户访问、更正、复制、删除与撤回同意等适用权利和渠道；
- 安全事件联系和处理办法；
- 是否存在境外传输及其具体路径。

个人信息处理的法定依据不只有“同意”一种，需区分合同履行等适用情形；若基于同意应满足自愿、明确和可撤回等规则。[L11]

### 5.4 用户上传他人资料
- 不默认学生对学院模板、同学源码、导师文件、商业开源外代码具有完整再分发授权。
- 提示用户确认拥有上传和处理所需权利；不要要求上传不必要的学号、身份证、成绩单。
- 模板授权和引用限制需另行核查；拥有一份文件不等于可将其公开纳入通用模板库。

### 5.5 委托处理/第三方共享
用户数据经第三方模型 API、邮件、云服务处理时，需据实际关系审查是委托处理、独立提供或共同处理，必要时通过合同约定处理目的、方式、范围、保护义务和删除，履行相应告知、评估、记录义务。[L11][L12]

### 5.6 个人权利与保留期限
- 页面/客服能受理账号、项目、文书的更正和删除请求；说明法定必须留存的部分。
- 文件删除必须覆盖原始、导出、缓存和按照备份策略到期清理的副本，不把“界面隐藏”当删除；原资料记录的“软删除可恢复”不等于隐私法意义上的真正删除。
- 保留期限根据目的最小必要、交易法定留存和安全/审计义务综合确定，**不得凭想象一律规定 365 天**。
- 安全日志和 AI 标识特别情形日志有不同要求，应建立分级保留制度。

### 5.7 不满14岁与特殊个人信息 [V]
目标是本科生并不等于不存在未成年用户，也可能有特殊数据。业务若实际处理不满 14 周岁儿童的个人信息或其他敏感个人信息，应分析特别规则及更严格的同意/安全措施；初期可通过适当限制高风险资料收集来减少暴露。[L11]

## 6. 模型和数据跨境：不因服务器在大陆就自动没有跨境

- 大陆服务器只说明 **Web/数据库宿主地**；模型路由、远程日志、监控 SaaS、邮件服务、代码仓库和第三方分析插件可能另有数据出境路径。
- 需要绘制数据流：用户设备 → 国内 Web/API → Worker → 哪个 API 域名/国家地域 → 模型处理/日志/备份 → 返回文书。
- 根据《个人信息保护法》和《促进和规范数据跨境流动规定》判断是否构成向境外提供个人信息、应否取得单独同意/采取跨境机制/是否适用豁免；**不将“人数少”当作无需其他义务的理由**。[L11][L13][L24]
- 数据不包含个人信息不代表没有保密、商业秘密、学校科研约束；特殊项目须另审。

**最低成本策略 [R]**：首期优先选择数据处理路径、留存条款和备案状态明确的服务商；默认只发送必要字段，不传完整仓库和无关私人文件。

## 7. 网络安全、上传源码与运营安全

### 7.1 法律基础
2026-01-01 已生效的修订版《网络安全法》以及 2025-01-01 生效《网络数据安全管理条例》，均涉及网络运行与数据安全责任。数据安全条例强调在等级保护基础上采取加密、备份、访问控制、安全认证等措施。[L12][L19]

### 7.2 必做技术清单（即使用户仅 5 人）
- **认证会话**：生产 HTTPS、Secure/HttpOnly Cookie、CSRF/Origin、登录限速、管理员强认证；生产禁用演示一键登录。
- **多租户隔离**：每个项目、文件、job、导出、缩略图、历史版本执行服务端 owner 核验，严测水平越权和管理员最小权限。
- **压缩包安全**：扩展名/MIME/文件头校验、大小与文件数限制、压缩比防 ZIP bomb、路径穿越/符号链接限制、病毒/恶意文件策略、隔离区、防止可执行宏和上传后反序列化；从不执行上传的程序。
- **模型提示注入**：用户文档中的指令不具有系统权限；限制工具权限、读取目录及输出范围，防秘密泄露和跨项目数据污染。
- **后台与密钥**：API Key、JWT 密钥在受控环境/密钥管理内；不入源码、日志、错误回显、可分享链接；人员账号权限按需分配。
- **基础部署**：容器最小权限、网关暴露最少端口，数据库/Redis 不对公网开放、磁盘加密/权限、补丁/依赖扫描。
- **可观测与响应**：异常任务、批量下载、误扣费、账号攻击、疑似数据泄露有告警和处置流程；避免日志记录源码/文书全文。
- **备份与恢复**：数据库/文件可恢复，备份与生产故障域分离，定期做恢复演练。

### 7.3 等级保护 [V]
应按实际业务、系统影响程度与主管机关指引开展网络安全等级保护定级及适用备案/测评工作。**不能写成“所有微网站上线必做二级等保测评”，也不能写成“小网站完全不需要等保”**。记录咨询和实际定级结果。[L19][L12]

### 7.4 重大安全缺陷即停
跨租户泄露、可执行用户上传脚本、远程命令执行、管理员越权、可绕过收费/导出权限、不可恢复的资料毁损等须隔离、修复、复验后开放受影响能力。

## 8. 学术诚信、内容真实性与导师信息

《学位论文作假行为处理办法》明确把论文买卖、代写、剽窃、伪造数据等纳入作假行为处理。[L16] Thesis Doc Suite 聚焦**资料整理、拟稿辅助和格式校验**，不是“提供可提交的学位论文代写成品”。

### 功能约束
- 不得虚构项目已完成的代码模块、测试值、实验结果、文献 DOI/作者；不把规划写成完成。
- 指导记录中的导师意见、指导时间、签名必须基于用户提供的真实信息，不能代造。
- 文献检索必须标明来源、出版信息，并由用户核对。不能把生成的“看似合理参考文献”当真实检索。
- 不能承诺直接提交、查重规避、论文包过、替代导师审批。
- 对学位论文或高校具体 AI 允许程度，依具体学校要求进一步判断；生成拟稿不当然符合校规。
- 风险内容通过“无法证实/需要补充”的小提示处理，不用长问卷压迫用户。

### 营销合规
严禁“代写论文”“包过答辩”“学校认证官方合作”或未经核实节省比例、实际客户评价等误导性承诺。展示示例用模拟或充分授权并脱敏的数据。[L15][L16]

## 9. DOCX 模板版权、开源组件与资产归属

- 学校公开 DOCX 模板供学生填写，不代表平台当然可将它们作为通用商用素材公开再发布；核查来源、使用许可、范围、保留标识及限制。
- 用户私人文书和源码默认仅为本人处理目的，不得未经明确授权拿来训练平台模型、发表案例或对外展示。
- 第三方开源仓库/Word 生成软件/图片/字体/图表库逐项扫描许可：MIT、Apache、GPL、AGPL、商业授权等条件不同；勿以“GitHub 公开可见”当作允许任意闭源商用。
- 如果使用 LibreOffice 等文档引擎，评估分发/修改/集成具体许可证与安装依赖；若调用商业 Office 自动化则同时审查服务器端支持与许可问题。
- 合作与委托开发软件的著作权需依据法律与实际书面约定判断。用户当前暂缓详细团队分成机制，但现有外部代码使用授权不可忽略。[L17]

## 10. 付费权益、支付、退款、消费者保护与税务

### 10.1 首期可先不收费
内部测试与第一轮有限免费试点可以用管理员发放试用权益，避免在产品质量未验证前建设支付系统；但不等于免费公网试点免除其他合规义务。

### 10.2 收费前检查
1. 经营主体及实际网络交易业务依法登记（有例外须核查）。[L14]
2. 经营性电信业务许可与网站备案的定性已核验，取得适用手续和凭证。[L01][L03–L05]
3. 微信支付/支付宝等**正规商户渠道**实际支持所选主体、网站形态、退款及结算；不要以个人转账截图或自动轮询个人收款码替代正式商户支付。
4. 明示商品：单项目服务范围、支持文书、任务额度、可预览与可下载的差别、服务期限（**不能将内部 365 天当成公示承诺**）、费用、售后与退款条件。
5. 用户支付前呈现重要条款，确认后保留可追溯的订单、权益、扣次、补偿、退款记录。
6. 发票、纳税义务、账务与资金结算根据主体和实际经营情况确定；不因小规模就省略。
7. 若未来自动续费，需要遵守显著提示等具体规则；当前项目包不等于已经确定订阅制。[L15]

### 10.3 数字服务退款问题
数字化文书服务涉及已消耗的 AI 生成任务、已交付文件、未使用权益，具体退款方案须依法结合服务性质明确，不能只写“虚拟产品一经售出概不退款”。依消费者权益法实施条例的真实、清楚告知要求设计。[L15]

### 10.4 营销分享换下载
此前“分享一次换一次下载，最多两次”只是建议，非上线已批准方案。平台可能对诱导分享有额外限制，Web Share API 也无法确认真实分享。首期不作为正式权益体系 P0。

## 11. 未成年人、账号、评论及社区功能边界

- 当前是一对一的文书辅助服务，不默认开放公开论坛、评论、作品广场或用户之间共享项目。这降低但不消除账号和内容安全义务。
- 《互联网用户账号信息管理规定》对账号管理、部分信息发布/即时通讯服务的实名要求有具体适用范围；**不能笼统说所有私人文书工具均必须收集身份证号**。采用邮箱/手机验证时依据实际服务和风险按需配置。[L20]
- 如新增公众发布、推荐流、模板社区、用户分享功能，可能增加内容审核、账号实名、算法推荐备案或其他专项义务，需重新评估。
- 不收集超出必要的学生身份信息；未成年人与敏感资料处理另审。[L11]

## 12. Windows Word COM 与中国大陆云 Linux 的技术/许可合规

### 12.1 已知事实 [S]
当前逐页渲染依赖本机 Windows MS Word COM，项目原资料明确写到；最新代码 Docker 完整模式未验证。

### 12.2 官方风险
Microsoft 表示不建议、也不支持无人参与/非交互式的服务器端 Office 自动化，涉及卡死、弹窗、并发、安全和许可风险。[L18]

### 12.3 需要形成的对比试验 [V]
- 输入：试点学校五类真实 DOCX 模板及各 3 份代表性内容样本，包含复杂表格、图片、页码、下划线、注释等。
- 候选：现有 Windows 作为基准、Linux 上经过许可审查的文档解析/渲染组件、可用的服务器端替代方案。
- 输出：生成 DOCX 可打开、文本/格式一致、分页偏差、中文字体可用性、页预览与 DOCX 对齐、转换失败率、并发资源。
- 判据：**无法稳定保留正式模板的路径不得上线此能力**。比较的是可靠交付，不是单看能不能输出 PDF。

## 14. 官方咨询顺序与预算优化

1. **属地通信管理局**：自营 AI 在线文书服务是否需经营许可，个体工商户的备案/主体适用性？
2. **ICP备案接入商**：按网站实际业务、主体类型和地域，查询域名及云资源备案清单；先核对再购买正式生产资源。
3. **属地网信部门**：API 调用已备案模型自身应用的登记/备案判定、公告信息与标识技术规则；保存咨询记录。
4. **属地公安网安部门**：公安联网备案及等级保护定级/适用程序。
5. **市场监管及税务部门**：主体登记、经营范围、网络交易经营者信息展示、付费与税务。
6. **模型/支付/云厂商**：合同和数据所在地、商户准入、退款、合规责任、事件处理。
7. 涉及学校模板授权与 AI 辅助使用规则，核实学校公开要求/必要时取得授权。

优先获取公开官方答复与现成在线政务材料，**不要在业务类别未确认前购买“代办 ICP 经营证”“快速 AI 备案”等收费服务**。
