# 内部质量验收与试点放行矩阵

状态：[C] 放行策略已确认；以下测试用例为 [R] 实施计划，尚未执行。

## 放行原则
首期实际开放核心功能通过验收即可有限试点，不必等未来通用模板、动态框架和插件市场全部完成。**受影响核心功能存在 P0/P1 时应修复、复验或移出试点范围**；不能以通过率抵消重大安全和事实问题。

| 级别 | 含义 | 策略 |
|---|---|---|
| P0 | 重大事实伪造、数据泄露/越权、核心流程无法完成、法律关键手续缺失 | 立即阻断受影响服务 |
| P1 | 模板关键结构错位、意见未应用、版本关系错误、任务成功率显著不达标 | 修复复验后放行受影响功能 |
| P2 | 一般 UX 缺陷、次要格式问题 | 有记录与处理计划，按影响评估 |
| P3 | 视觉和微交互 | 可后续迭代 |

## 必须执行的测试样本
1. **真实完整项目**：有授权源码、技术文档、必要图表和真实测试资料，验证最完整主流程。
2. **缺失证据项目**：没有实验结果/参考文献，验证不伪造、不把规划写为完成。
3. **更新资料项目**：新材料影响旧文书，验证信息更新提示和版本关系（若首期未开放此能力，则标“未来能力未开放”，不得假验收）。
4. **模板复杂样本**：固定标题、表格、下划线、页眉页脚、图片、编号和分页；WPS/Word 双端查看。
5. **恶意/越权样本**：其他用户的项目 ID、直接文件下载 URL、损坏 ZIP、提示注入、重复提交等。

## 决策
- Go：实际开放范围内全体 P0、P1 验证通过、合规清单满足适用要求。
- Adjust：非关键问题限范围开放，受影响功能关闭且说明用户实际可用范围。
- Hold：关键证据不足、法律准入或隐私无法确认、严重风险尚在。
