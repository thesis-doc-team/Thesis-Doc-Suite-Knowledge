# Thesis Doc Suite｜内部知识资产包 V1.0

> **性质：内部研究与决策资产，不是对外宣传材料、法律意见或已通过验收的工程证据。**
>
> 归档基准：2026-11-09｜市场：中国大陆，本地一所高校首轮试点｜目标部署：中国大陆云服务器。
>
> 项目正式工程：`thesis-doc-web`；原项目介绍声称仓库为 `https://github.com/thesis-doc-team/Thesis-Doc-Suite`，本次**未独立扫描代码或访问仓库进行验证**。

## 先读这里

**一句话定位**：首期是以实际项目资料为基础的本科毕业设计过程文书整理、拟稿、模板编排、审阅修订平台；长期演进为**AI 资料理解 + 通用文书框架库 + AI 动态构建 + 场景插件**的智能文档编排平台。

**当前绝对不能混淆的三件事**：
1. `已讨论确认`≠`已经开发实现`≠`已经经过实测`。
2. `免费受限高校试点`≠`已经取得公开经营、提供生成式 AI 服务、收费的全部手续`。
3. `通用文书框架`≠`任何高校强制格式`；用户正式模板与合法有效的特定要求优先。

## 信息状态标记（强制）

- **[C] 已确认决策**：本轮对话中用户明确选择。属于产品规划承诺，不是实现证明。
- **[S] 原始材料声称现有**：项目介绍/会议纪要中写到的事实、测试结论，**未经本包独立验收**。
- **[R] 建议方案**：可供选择的实施建议，非已确认需求或法律最终结论。
- **[V] 待验证/待主管机关确认**：不能标注合规完成或技术已可用。
- **[H] 暂缓事项**：项目当前明确不讨论或不开发。

## 核心阅读约束

1. 对外宣传优先参考 `01` 中的**当前真实能力**，且将 `[S]` 表述为“项目原资料记录”，上线前再次核验。
2. 需求开发先读 `03` + `04`，再对照正式工程 `docs/knowledge`、`docs/features` 与代码；**不得凭知识包假定代码已经支持未来功能**。
3. 对外试点必须通过 `06` 的开放功能质量门槛和适用合规条件；“小范围邀请”“免费”不构成当然豁免。
4. 法规索引仅代表 **2026-11-09 的公开资料研究快照**；地方实施口径、网站性质、主体资格、供应商位置不明时必须再次核查。
5. 严禁编造项目事实、实验结果、导师签字/意见、参考文献或将拟稿宣传为可直接交付学术评审的终稿。
