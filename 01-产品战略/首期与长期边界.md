# 首期与长期产品边界

## 首期允许开放的目标 [C]
- 仅围绕**本地一所高校**已验证的本科毕业设计过程文书，试点范围取决于真实模板及能力验收。
- 保留现有**单项目串行工作流**：技术资料 → 事实/技术文档 → 审阅确认 → 派生 Word 文书。
- 第一轮邀请熟人中 5–10 位有真实需求的同学，用户独立操作、遇到障碍求助。人数为建议量级，不是抽样统计阈值。
- **首期实际开放的功能必须通过准入测试**；非核心的规划功能不用全做完才试点。

## P-01 声称已实现（仅资料记录 [S]）
- 账号认证、单项目工作台、源码/资料上传和静态分析。
- 项目技术文档（Markdown/HTML）、项目事实台账。
- 毕设任务书、开题报告、文献综述、中期检查记录、毕业设计指导记录的 DOCX、官方模板校验与逐页预览。
- 文书版本、逐页意见、管理后台、素材库、反馈、日志中心等。
- 2026-11-03 五类 Word 文书被记载为“用户验收”，但完整最新代码的从零真长跑尚未重新验证。

## 已知缺口和约束 [S]
- “强调生成”仅写入选项，Worker 尚未使用：GAP-001。
- 工程实施方案的后端读取权限尚未强制。
- `contracts/openapi.yaml` 与全接口不完全同步。
- Docker 完整模式与最新版长流程验证不足。
- 当前 MS Word COM 依赖 Windows 本地环境；目标中国大陆 Linux 云部署须验证替代方案。
- 毕业论文结构参考/排版检验是规划能力，不能认作已上线。

## 远期能力：不得混入首期承诺 [C-规划]
- 经过验证的通用文书框架库 + 未知文书类型由 AI 动态建议框架。
- 选择场景、AI 推荐场景、用户自然语言从空白创建场景并确认。
- 用户 DOCX 模板/要求覆盖默认结构和格式，兼容规则被复用。
- 多项目、多文书场景跨类复用，具体工作台形态待验证。

## 明确不作为当前目标 [H]
- “先覆盖全国高校毕设模板”的独立产品阶段。
- PPT 生成、插件商城、复杂自定义执行代码、公开共享场景市场。
- 正式团队分成、合作成员报酬机制细节（用户明确暂缓）。
- 365 天服务期限为**内部测试暂定配置**，非商业承诺。

## 版本纪律
对外“现有功能”以正在运行的代码和验收记录为准，而非以此文档的[S]清单为准。
