# 首期商业模式与成本测算

## 已确认的机制 [C]
- 本地高校微试点的方向：**免费有限体验 + 单项目付费完整服务包**。
- 免费允许分析与有限生成、全页预览；下载按后端授权。
- 全项目共享成功生成/修订任务额度池，不按文书种类拆；系统失败不扣。
- 不确定的价格、额度、服务期不对外承诺。365 天只是内部配置。
- 长期通用平台的收费模式完全未决定，需重新验证。

## 单位经济模型 [R]
一次用户目标文书总成本 ≈ 输入资料处理费 + 事实抽取模型费 + 文书模型费 + 编排渲染算力费 + 存储/传输 + 失败重试成本 + 人工支持摊销 + 支付通道手续费/税费（收费时）。

计算并记录：
- `job_success_rate`, `model_input_tokens`, `model_output_tokens`, `cost_per_successful_doc`；
- `retry_count`, `render_time`, `manual_support_minutes`, `storage_bytes`, `export_count`；
- 每项目平均已生成文书数、修订次数、可重用信息比例。

## 低成本部署原则
1. 以当前 FastAPI + PostgreSQL + Redis/RQ 单机为优先研究方向；根据**真实内存和并发**选择配置。
2. AI 调用外部 API，通常无需首期自建 GPU；需要审查模型调用地及数据处理协议。
3. 增加单任务、单项目、单用户、全平台预算与速率限制。
4. PostgreSQL 数据库与独立备份分离；有恢复测试。
5. 不采购 Kubernetes、专门 CRM、复杂监控/营销等与首期试点无关的系统。
6. 当前 Windows Word COM 服务化需验证替代方案与许可，**Word 兼容性优先于最低服务器价**。

## 收费阶段门槛
合法经营主体/适用手续、支付商户审核、商品介绍、服务期限、生成额度、退款机制、客服入口、交易记录、发票和税务要求需完成相应核查之后才能收真实款项。

## 与历史会议的差异
P-02 提到 API Key 轮换平台优先、营销先行等早期建议；当前以真实核心功能验收、低成本试点为优先，不将复杂路由平台作为无条件 P0。
