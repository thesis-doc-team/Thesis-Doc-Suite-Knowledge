# 本地高校试点、反馈与低成本获客

状态：[C] 策略已确认；试点具体人选、日期和场地未定。

## 试点设置
- **一所本地高校**；**熟人定向邀请**，目标 5–10 名有真实毕设资料与任务的学生。
- 建议分两批：先 2–3 名深度反馈，再 3–7 名偏独立使用；不是统计随机抽样。
- **用户自己操作，遇到问题主动求助**。记录自主成功、求助后成功和失败三种不同结果。
- 邀请制不当然免除备案、个人信息保护、AI 服务适用要求；以第 06 模块放行判断为前提。

## 真实任务流程
确认支持的模板及资料来源 → 提供必要隐私与试点告知 → 用户操作 → 留存脱敏任务指标和授权产物 → 一次简短访谈 → 缺陷分级 → 修复和复验。

## 试点指标
| 指标 | 数据来源 | 解释注意事项 |
|---|---|---|
| 无指导完成率 | 任务和求助日志 | 不能混入开发人员代操作 |
| 端到端完成时间 | 前后端事件/用户自述 | 含准备资料和自行修改时间 |
| 内容事实错误率 | 样本人工逐项核对 | “写得流畅”不等于正确 |
| 排版错误数量 | 官方模板逐页核对 | 精确记录页/对象/严重程度 |
| 第二份文书重复输入量 | 操作事件与访谈 | 验证核心“资料复用”价值 |
| 留存与复用 | 再次实际登录和生成 | 口头意愿与行为分开 |
| 付费证据 | 明确报价选择、实际订单（收费后） | 免费试点不等于真实转化 |
| 单项目完整成本 | 模型、任务、人工、存储 | 包括失败和售后成本 |

## 反馈表最小字段
`用户编号`、`试点波次`、`场景/目标文书`、`资料类型`、`支持模板版本`、`自主/求助/失败`、`问题分类`、`严重级别`、`证据链接`、`复验状态`、`匿名反馈摘要`、`研发任务 ID`。

## 反馈优先级
P0 事实重大伪造、越权访问/导出、核心流程不可达；P1 关键格式严重偏移、修订意见丢失、版本错乱；P2 一般操作体验；P3 视觉和微交互。先确保安全和结果质量，再决定新功能。

## 低成本获客顺序 [C]
1. 熟人定向试点：获得实际结果而非流量。
2. 自愿口碑推荐：不强制转发、不共享私人项目链接。
3. 模拟/授权材料的视频演示：展示资料理解、Word 编排、修改闭环；不宣传“代写包过”。
4. 产品合规上线后再小规模尝试校园社群、内容平台与技术社区；真实获客成本与任务转化高于单纯浏览量。

## 拒绝的过早指标
不以 5–10 人推断全国市场、不使用未经验证的转化率假设、不因“很多人觉得不错”立即大规模买流量。
