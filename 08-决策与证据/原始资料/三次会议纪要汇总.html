01

核心结论

三场会议串起来是一条主线：先把产品从“毕设工具”拔高成通用平台，再用合规话术重构商业模式，最后回到客户身上回答“凭什么买”。

与开源竞品相关的合规关注点

  1. 产品定位：从“专属模板”转向“通用检索 + 定制交付”。剥离学校／单位属性，先当黑盒产出标准化通用内容，再按用户格式要求由 Agent 二次加工，形成“通用版 + 定制版”双输出。

  2. 商业模式：从“卖成品”改为“卖服务”。不再直接售卖成体系的毕业论文文本，改为提供信息提取、模板填充与排版校验，规避代写的合规红线，同时保留收费能力。

  3. 底层优先级：API 通用平台排在最前。单一 API 存在调用失败、超支与被断供风险，需做多接口 Key 转换与轮换机制；文档引擎则拆为“信息拆解”与“Word 编排”两个独立模块，为平台化铺路。

  4. 客户答案：专治“懒”与“不会排版”。核心价值不在“帮你写内容”，而在“帮你省掉格式、图表、文献综述的苦活”，目标客群落在金字塔中低端的本科／普本学生。

  5. 节奏：先上线验证，再补合规与推广。三次会议一致接受“粗糙 MVP 先跑通”的策略，上线时点被反复提到（下周内／15 号／本周末），但口径未统一，是当前最需要钉死的里程碑。

第一次项目方案与排期研讨邓淇 · 宁梓淇

搭骨架：定通用化方向，切开发任务，排上线时间

参会：邓淇、宁梓淇（另有元宝会议助手全程记录）

  • 确认产品走通用型版本，不再限定特定学校或单位的专属模板，改为基于大规模检索生成通用排版。
  • 确立通用与定制双输出机制，并明确“以用户要求为最高标准”。
  • 抛出三项核心开发需求：API 平台兼容、Word 文档引擎、PPT 生成（参考 PPT Master，先出 HTML 再截图）。
  • 决定优先升级现有六类文本 Skills，保证小范围内先能用；通用化重构因难度大而暂时搁置，先优化现有功能抢上线。
  • 敲定服务器采购与部署分工，同步推进宣传视频；营销只做小范围试水，并考虑拉“一堂”入伙负责运营。
基调：务实抢跑——“先落地再升级”，把“做产品”和“找方向”的活儿彻底拆开。
第二次AI 论文辅助工具创业研讨引入外部顾问

补漏洞：合规红线、商业模式转型与获客路径

参会：邓淇、嘘声、宁梓淇

  • 邓淇向嘘声完整复盘项目：基于 AI Agent 的通用文本工具，用户上传文本或源码，Agent 提取信息点作为唯一信息源，生成任务书等六类文本，要求统一格式、符合逻辑框架、自动产出流程图／三线表等图表。
  • 披露进度约 60%–70%，框架已成型但未上线，仅有宣传视频，计划本周末前上线首版。
  • 嘘声直指代写论文属灰色地带，缺备案与资质极易被举报封号下架；邓淇随即提出转型方案——不卖成品，只做“信息提取 + 模板填充 + 排版”。
  • 客群出现分歧：邓淇主张覆盖全体有汇报需求的大学生，嘘声主张避开高学历群体、主攻金字塔中低端。
  • 嘘声贡献产品视角：需求表新增“作用／用户视角”列，把“Skill”通俗化为“功能”，并梳理运营上传到 QA 审核交付的全链路。
  • 推广方向成型：熟人圈层与校内试点、小红书自媒体、GitHub 开源竞品调研与引流。
基调：被外部顾问“挤牙膏”式追问，把包装层剥掉，逼出真实业务内核——“帮你改东西”。
第三次客户需求与差异化邓淇 · 嘘声 · 宁梓淇

找理由：客户为什么非买不可

参会：邓淇、嘘声、宁梓淇

  • 宁梓淇把产品直白定义为“懒人式”论文生成工具：上传源码即可一次性拿到成品，不必反复与 AI 对话修改。
  • 邓淇补足动机：普本院校学生缺写作经验，在格式排版、文献综述、表格填充上耗时极长，甚至要重新学 Word——核心价值从“生成内容”降维到“解决排版焦虑”。
  • 宁梓淇提炼痛点三条：懒得写、懒得学、懒得反复打磨；嘘声用客户金字塔把三类人分层拆开。
  • “论文转 PPT”增值服务被提议后被否：对论文有要求的用户更愿自己调教 AI，与服务定位错位。
  • 收尾定了两件大事：完成产品上线 + 获取官方认证；日常技术与运营由邓淇、宁梓淇推进，重大事项再拉三人会议。
基调：回归用户——“人唯一不变的就是懒”，用固定框架替代重复劳动。
03

产品定位的三级跳

三次会议对“这是什么产品”的回答逐层抬升，最终落在平台化服务上。

起点 · 原始设想

毕设文本生成网站

面向毕业设计的文本生成工具，靠“一键出稿”直接变现，规模与合规空间都受限。

›
第一次 · 抬升

通用文本编排工具

剥离学校／单位属性，做通用模板 + 定制化二次加工，支持论文、汇报、比赛等多类文本。

›
第二次 · 转向

信息编排服务平台

不卖成品卖服务：信息提取、模板填充、格式排版与校验，用“代编排”规避代写风险。

通用版与定制版的双输出

系统先把项目当黑盒，产出标准化通用内容；再基于用户上传的格式要求（或定制模板）由 Agent 二次加工，交付定制文档。若用户已提前给出模板，则跳过通用模板环节，直接加工。

以用户要求为最高标准

若用户要求的格式比通用模板更简单，优先交付用户要求的部分，把多出来的内容作为“建议项”附上，既保底又留灵活度——即“基础交付 + 增值建议”。

标准交付流程

第一次会议对工作流做过一次“做减法”，最终收敛为四段式。

输入
源码 / 资料 + 格式要求
用户上传项目源码或文本资料，并提出格式、结构要求。
→
提取

Agent 抽取唯一信息源，锁定后续全部生成内容的依据。
→
编排
通用内容生成
按标准框架产出统一格式、逻辑自洽的文本，并自动配套流程图、三线表等图表。
→
交付
定制加工 + 建议项
按用户模板二次加工输出，超出部分作为建议项供用户取舍。
单一信息源所有文本共用同一套提取结果，从源头规避数据前后冲突。
格式即交付物统一格式、逻辑框架、图表自动生成，是用户“怕麻烦”的核心解药。
人工留出口用户可在推荐内容基础上修改或替换，最终审阅权留在用户手里。

06

风险与合规

第二次会议的核心增量：外脑把合规摆到了台面上，并给出了转型出路。

高风险

直接代写论文的合规红线

直接生成整套毕业设计文本属灰色地带，缺少合规认证与备案时，极易因举报被平台下架或承担法律责任。

应对：转型为信息提取与排版服务，并完成网站备案与资质办理。

高风险

开源协议的侵权风险

借鉴 GitHub 开源项目功能时需保留私有代码；若商业化后闭源使用开源代码，存在协议纠纷风险。

应对：只做功能层“仿造”而非底层逆向，明确代码边界与许可范围。

中风险

被通用 AI 平替

大学生普遍会用 AI，若产品只提供“生成内容”，很容易被免费工具覆盖。

应对：用“省去反复修改与排版”的性价比构建护城河。

中风险

开源引流暴露操作逻辑

用开源前端换 GitHub Star 的提议被否——前端一开源，操作逻辑即被完整暴露、易被逆向。

应对：改为反向借鉴同类项目分支，不开源核心链路。

中风险

单一 API 断供与超支

全部能力压在一个接口上，一旦失效或计费异常，业务直接停摆。

应对：API 通用平台 + 多 Key 轮换，作为第一优先级开发。

中风险

错过窗口期被竞品抢先

竞品可能靠营销抢市场，“酒香也怕巷子深”，产品与营销必须双线并行。

应对：加快开发、尽早上线，宣传视频与研发同步推进。

客户画像与差异化

第三次会议把“谁会买”拆成了金字塔，第二次会议已定调：优先主攻中低端。

图中金字塔为按会议口述结构自绘的示意图，用于说明分层逻辑，不代表实际用户占比。

核心价值：解决排版焦虑，而不是替你思考
统一格式、逻辑框架、自动配图表（流程图、核心框架、三线表），把最耗时的苦活自动化。
差异化：省掉“反复打磨”这一环
对“懒得改”的学生，产品充当师生之间的传话筒：按导师反馈批量修订，避免一次次重开对话。
明确不做的：高要求用户增值服务
“论文转 PPT”一类增值项被否——目标用户不愿付费打磨，高要求用户则自己调教 AI。
08

增长路径

从熟人裂变到自媒体，再到技术社区，三层递进；核心原则是“先有产品再谈推广”。

第一层 · 熟人

校内试点与老同学圈层

从自身院校起步，小范围测试产品效果、积累初始用户；早期靠核心骨干拉客源，跑通后再下放管理权并招新。

第二层 · 自媒体

小红书等平台合规展示

以“产品自测／功能演示”的合规口径展示能力，规避代写话术；嘘声负责研究公域与私域的具体搭建方法。

第三层 · 技术社区

GitHub 竞品调研与借力

盘点同类开源项目功能以查漏补缺；直接开源前端换 Star 的方案被否，改为借鉴分支思路。

转化预期
“100 人转化 10 人”的试水目标被嘘声判定过高，试错成本需要重新校准；推广的前提是先有能跑通的成品。
团队分工
日常技术与运营由邓淇、宁梓淇推进；嘘声聚焦数据分析与方法论，重大事项拉三人会议同步。
