# 知识导航与 Agent 使用规则

状态：[C] 资产维护规约｜版本 V1.0｜2026-11-09

## 1. 资产边界
本知识包记录**是什么、为什么、怎样验收、下一步验证什么**；它**不是**可直接替换正式代码、合同、备案材料的产物。

阅读优先级：`README` → `01/02`（战略和用户）→ `03`（首期需求）→ `04`（长期技术方向）→ `06`（质量与合规）→ `08`（决策证据）。按任务选择，不要求 Agent 无差别加载全部目录。

## 2. 标准术语
- **场景插件（场景包）**：一个任务环境的声明式配置，包括任务目标、文书集合、输入资产、流程、校验规则；不代表上传用户代码直接运行。
- **文书框架**：某文书类型的内容逻辑、默认样式、规范与校验要求；不同于具体官方 DOCX。
- **具体模板**：用户/学校给出的 Word 文件及其结构、标题、表格、固定文字和排版约束。
- **工作空间**：承载一次具体项目的源资料、事实、生成任务、审阅和版本。不能与可复用场景包混同。
- **信息资产**：带来源、确认状态、时间与适用范围的项目事实和用户重点，支撑多文书复用。
- **拟稿**：供用户核对、修改和确认的参考输出，不代表最终学校认可或保证合规。
- **任务额度**：一次符合规则的生成或修订任务消耗共享池；导出权是另一权限维度。

## 3. 变更规范
每一项新事实以 `来源/检验时间/验证方式/结果` 记录；需求变更以 `ID/原决策/新决策/原因/受影响文件/是否需要研发迁移` 记录。会议信息为输入历史，不覆盖后来用户明确确认的决策。

## 4. 三级验收证据
- 源码/架构事实：文件路径、代码行号、commit、运行命令；无这些证据标 `[S]`。
- 产品体验事实：测试任务、真实/授权数据、截图或产物、用户操作结果。
- 合规事实：官方法规、适用条件判断、主管机关答复/备案凭证/供应商协议，不得以猜测标记“通过”。

## 5. 不可自动执行
未经明确授权不得上传用户材料给第三方、修改正式服务、读取仓库机密、注册主体、购买云资源、上线支付或代表用户办理备案。长期功能不会在首期自动启用。
